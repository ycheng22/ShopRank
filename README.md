## Metrics & Conventions

Every number in this README was produced by `evals/runner.py` and written to the
`eval_runs` table. Tables are generated by `evals/ablation.py`, never hand-edited.

### Relevance judgements

| ESCI label | Meaning | Gain |
| --- | --- | --- |
| E | Exact | 3 |
| S | Substitute | 2 |
| C | Complement | 1 |
| I | Irrelevant | 0 |

Gains are **hardcoded, not configurable**. Papers on this dataset differ — some
score Complement as 0 — so an NDCG figure is meaningless without stating its
mapping.

- **"Relevant"** (used by `recall@k` and `MRR@k`) means **gain > 0**, i.e. E, S
  and C all count. A stricter "Exact only" definition is equally defensible and
  yields visibly lower recall; the point is that one definition must be picked
  and stated, or recall and NDCG in the same table describe different things.
- **Queries with empty qrels are skipped**, never scored as 0. Every run reports
  how many were skipped. Scoring them as 0 would drag the mean down uniformly
  across all pipeline stages — invisible in an ablation table, and easy to
  misread as "my change did nothing".
- NDCG uses linear gain with a `log2(rank + 1)` discount. `k` larger than the
  result list is handled, not an error.

### Dataset

Amazon ESCI, filtered to **`small_version == 1` AND `product_locale == "us"`**
(the standard Task 1 ranking subset, 29,844 queries). The variant is frozen
because the thresholds below are percentiles measured *on it* — the same 40th
percentile on the full US set is 0.688, not 0.312.

| Constant | Value | Why |
| --- | --- | --- |
| Queries | 1,500 (900 / 300 / 300) | ESCI products barely overlap across queries (~19.3 unique products per query), so 1,500 queries ≈ 29k products, just under the 30k corpus cap |
| `difficulty_bin` | hard iff E-fraction ≤ **0.312** | 40th percentile on this variant |
| `candidate_size_bin` | large iff ≥ **16** candidates | the median; only 19.5% of queries have ≥20, so the original ≥20 threshold made the target ratio unreachable |
| Seed | 42 | hardcoded and logged |

Splits are stratified on five dimensions **by query**, so no query's candidates
leak across splits. The test split is read only via an explicit
`allow_test=True`; the default is dev.

### Sampling is deliberately skewed

The sample over-represents hard cases (**60% hard**, **≥20% with a Complement
label**). ESCI is 65% Exact at the pair level, so a representative sample would
let BM25 answer most queries correctly and compress every pipeline stage's
contribution into a rounding error.

### Why absolute scores are low

Retrieval runs over the **full 30k corpus**, not within each query's own
candidate set. This is the realistic setting and the only one where `recall@50`
means anything, but ESCI labels only each query's candidates — so a retrieved
product with no judgement counts as irrelevant.

> Combined with the hard-case over-sampling, absolute scores here are **not
> comparable** to ESCI leaderboard or reranking-task numbers. **Only the deltas
> between rows of the ablation table are meaningful.**

### Known measurement limitations

- Candidate sets are small (median 16), so reranking has limited room to
  reorder. Expect a modest contribution from that stage.
- Chinese and French query sets are machine-translated (`translate_queries.py`),
  used only for cross-lingual recall — never for absolute ranking quality.
